## Продукт: то, без чего звонок бесполезен

- [ ] **1. Закрыть движок на домах, которые можно продавать.** Сейчас сборка 59 уже рисует стены, окна и двери, расставляет стойки, королевские, джеки, перемычки, калифорнийские углы, считает раскрой шестиметровых досок и смету в рублях. Этого мало. Движок должен стабильно проходить ортогональный одноэтажный и двухэтажный дом с двускатной, вальмовой, односкатной или плоской крышей, замкнутым наружным контуром, проёмами, которые лежат внутри стен, и внутренними перегородками с узлами примыкания. На выходе без ручной склейки должны получаться план каркаса, фасад, торец, план стропил, развёртка каждой стены с king/jack/header, ведомость элементов, раскрой, смета и список предупреждений. Эталон — дом примерно 6×8 м из текущего демо: после любой правки кода он пересчитывается тем же скриптом `npm run smoke` и не меняет ожидаемые стойки, длины и предупреждения без явного решения. Косые стены, эркеры произвольной формы, ломаные крыши с ендовами, фундамент, крепёж, ветер и «полный СП 20/64» в этот пункт не входят. Если такой дом нельзя посчитать дважды с одним результатом, к экспорту не переходи.

- [ ] **2. Сделать блокирующую диагностику до любого отчёта.** Перед каркасом, сметой и экспортом запускается preflight. Критические ошибки — незамкнутый наружный контур, наружная стена вне ортогонали, проём, который не лежит на стене, пересечение геометрии, отсутствие опоры там, где движок всё равно пытается повесить балку, неподдерживаемый тип крыши. На такие ошибки нельзя молча выдавать красивую ведомость: кнопка экспорта для закупки не работает, на плане подсвечивается место, рядом короткая причина и что сделать руками. Предупреждения вроде «пролёт на границе таблицы» не блокируют черновик, но помечают его. Пользователь кликает по ошибке, исправляет стену, preflight пересчитывается без перезагрузки проекта. Готово, когда на специально сломанном доме экспорт закупки не создаётся, а после замыкания контура создаётся.

- [ ] **3. Поставить карту покрытия первой страницей любого отчёта.** Это не «ещё один дисклеймер в подвале». Это паспорт расчёта, который человек видит раньше чертежей. В разделе «проверено» должно быть прямо названо: ортогональные стены, один или два этажа, перечисленные типы крыш, расстановка стоек и проёмов, табличные пролёты, прогиб L/360 при укрупнённых нагрузках, раскрой по заданным хлыстам. В разделе «не проверено» — фундамент, геология, ветер, региональный снег, пространственная жёсткость, узлы крепежа, влага, огонь, инженерия, косая геометрия, любые нормы кроме явно указанной редакции СП 31-105-2002. На этой же странице фраза: инструмент предварительного проектирования и оценки, не замена лицензированного конструктора и локальной проверки. Готово, когда эта страница есть и в интерфейсе, и на первой странице PDF.

- [ ] **4. Дать компании свой сортамент, цены и правила распила.** В настройках появляется каталог фирмы, а не скрытые константы в коде. Профессионал один раз вводит доступные сечения, длины хлыстов, цену пиломатериала за куб, цену листа и утеплителя, ширину пропила, закупочный запас и свои названия позиций. Эти значения становятся умолчанием для новых проектов и не переписывают уже посчитанный старый дом, если он открыт через месяц. Раскрой использует его длины, а не всегда 6 000 мм. Смета считает его цены, а не демонстрационные. Готово, когда два проекта одной фирмы получают один прайс по умолчанию, а изменение глобального прайса не меняет сумму уже зафиксированного экспорта.

- [ ] **5. Сделать PDF-альбом, который можно отправить без FramePlan.** Файл открывается у клиента, бригадира или проверяющего на любом компьютере. На титуле — название проекта, версия модели, номер сборки приложения, дата и время формирования. Дальше карта покрытия и оговорка из пункта 3. Затем план каркаса, фасад, торец, план стропил, развёртки стен, сводка прочности, ведомость материалов, раскрой. Если в модели есть критические ошибки, коммерческий PDF не собирается. Если есть только предупреждения, собирается черновик с водяным знаком «не для закупки». Готово, когда демо-дом 6×8 выгружается одной кнопкой, без скриншотов и без ручной вёрстки, и числа в PDF совпадают с тем, что видно на вкладках «Смета» и «Раскрой».

- [ ] **6. Сделать CSV для Excel: что купить и что пилить.** Два файла или два листа. Первый — закупочная ведомость: группа, наименование, сечение, единица, количество, цена, сумма, примечание, номер сборки, дата. Второй — поэлементный раскрой: категория, сечение, длина детали, количество, метка, номер хлыста, длина хлыста, отход. Кодировка UTF-8 с BOM, чтобы Excel на Windows не ломал кириллицу. Готово, когда строка стойки 50×150 в CSV совпадает с интерфейсом с точностью до штуки и миллиметра, и этот файл открывается двойным кликом в Excel и Google Таблицах.

- [ ] **7. Замкнуть цикл файла проекта.** Сейчас JSON можно скачать, но нельзя штатно открыть обратно. Нужны: открыть `.frameplan.json`, сохранить как, дублировать, переименовать, список локальных проектов в браузере, понятная команда «скачать backup» и «восстановить из файла». Облако, аккаунты и пароли в этот пункт не входят. Готово, когда проект выгружается на флешку, открывается в другом браузере и даёт тот же BOM, а очистка сайта в одном браузере не уничтожает единственную копию, если backup скачан.

- [ ] **8. Поставить версию, сборку и дату на каждый уходящий наружу файл.** На каждой странице PDF, в шапке CSV и внутри JSON должны быть имя проекта, внутренний номер версии модели, `APP_BUILD` и время экспорта. После изменения стены номер версии модели растёт. После изменения алгоритма растёт сборка. Готово, когда по одному PDF можно сказать, какой билд его сделал, и два файла одного дома, посчитанные до и после фикса, не путаются.

- [ ] **9. Сделать режим сверки со старой ведомостью клиента.** Человек загружает CSV или вводит несколько итоговых позиций руками: «стойка 50×150 — 84 штуки», «ОСП 12 мм — 46 листов». FramePlan сопоставляет названия со своими категориями, показывает абсолютную и процентную разницу и не объявляет клиента идиотом. У каждого расхождения есть поле причины, которое ставит человек: дефект FramePlan, неподдержанный случай, кривой ввод, другая допустимая традиция узла, вероятная ошибка исходной ведомости. Из одной кнопки собирается таблица «было → стало → разница → причина → комментарий» в PDF и CSV. Готово, когда на демо-доме можно вручную ввести заведомо другие числа и получить эту таблицу за один проход, пригодную к показу на звонке.

- [ ] **10. Зафиксировать один эталонный дом как известный правильный ответ.** Возьми простой прямоугольный дом из демо, вручную проверь стойки на одной стене с проёмом, углы, длину хлыстов и несколько строк сметы. Запиши ожидаемые числа в smoke-тест. После этого любой фикс, который меняет эталон, должен падать в `npm run smoke`, а не «почти так же, но на две стойки меньше». Готово, когда тест красный, если угловую стойку «упростили», и зелёный на текущем правильном результате.

- [ ] **11. Убрать из интерфейса формулировки, которые звучат как готовый проект.** В шапке, на вкладке прочности и в экспорте не должно читаться «можно строить» или «полный расчёт по СП». Должно читаться: предварительная модель платформенного каркаса по указанной редакции, табличные проверки, требуется конструктор. Готово, когда человек, впервые открывший демо, за две минуты понимает и ценность, и границу ответственности.

- [ ] **12. Не делать до первых трёх оплат.** Пока три пилота не оплачены, в репозиторий не входят: импорт SketchUp, DXF, IFC, CNC, фотореалистичный 3D, маркетплейс, кнопка «заказать домокомплект», облачные аккаунты, роли, realtime, карточный checkout, полный решатель по СП 20/64, фундамент по геологии, фермы, панели завода. Если клиент просит это на звонке, запиши запрос в таблицу и вернись к сверке его старого дома. Готово, когда в git history за период до трёх оплат нет коммитов по этому списку.

## Сайт и домен: одна витрина, один редактор

- [ ] **13. Купить один домен и повесить его на текущий GitHub Pages.** Редактор уже открывается на `https://s7v7nth.github.io/frameplan/`. Не покупай отдельный WordPress-хостинг, Astra, Elementor и SiteGround: это стек другого бизнеса и лишние 80–300 долларов в год. Домен регистрируй там, где его можно оплатить из Беларуси без театра: Beget, Timeweb или REG.RU для зоны `.ru`; Cloudflare Registrar, если берёшь `.com`. Нужен короткий адрес вроде `frameplan.ru` или `frameplan.app`. В DNS сделай A/CNAME на GitHub Pages этого репозитория, в настройках Pages укажи custom domain, включи HTTPS. Готово, когда `https://твой-домен/` открывает то же приложение, что и GitHub Pages, с рабочим сертификатом.

- [ ] **14. Сделать продающую страницу `/ru/pro`, а не «главную с девятью пунктами меню».** Первый экран: заголовок «Каркас, спецификация и раскрой без ручного пересчёта в Excel». Подзаголовок: FramePlan строит геометрию платформенного каркаса, формирует ведомость и раскрой, сравнивает варианты и отмечает места, которые обязан проверить конструктор. Кнопка: «Проверить на завершённом проекте» — она ведёт на запись разговора или на Telegram/телефон из пункта 20. Ниже на той же странице, без отдельных «о нас»: видео 45–90 секунд без голоса, схема «план → каркас → PDF/CSV», прямое сравнение со SketchUp плюс Excel, пустой каркас под таблицу реальной сверки, список поддержанного и не поддержанного, кнопки скачать образец PDF и CSV, пакет за 2 900 ₽, твоё имя, город/страна работы, телефон, почта, Telegram, ссылка на редактор как на инструмент, не как на единственный CTA. В подвале — оговорка из пункта 3 и ссылки на условия и политику. Готово, когда незнакомый проектировщик за одну минуту понимает, что купит, и может нажать «проверить» или позвонить.

- [ ] **15. Записать одно демо на 45–90 секунд.** Открой эталонный дом, не свой рабочий стол с почтой. Покажи: нарисовал стены и проём, открыл каркас, открыл раскрой, скачал PDF. Без музыки, без интро, без «привет, меня зовут». Наложи две-три подписи: «план», «каркас», «файл для клиента». Выложи на страницу `/ru/pro` и в Telegram-описание. Готово, когда ролик смотрится без звука и за полторы минуты доходит до файла.

- [ ] **16. Положить на сайт образец PDF и образец CSV эталонного дома.** Это те файлы из пунктов 5 и 6, с картой покрытия, сборкой и датой. Рядом одна фраза: «это демо-дом, не чей-то реальный объект». Готово, когда файлы скачиваются без регистрации и открываются без FramePlan.

- [ ] **17. Написать короткие юридические страницы до первого платежа.** Нужны условия использования, политика конфиденциальности, оговорка о границах расчёта, правило возврата для пилота и запрет использовать результат как рабочую документацию без конструктора. Это ещё не «пакет корпоративного юриста». Это текст, который можно показать бухгалтеру и клиенту. Готово, когда ссылки с `/ru/pro` открывают эти страницы на том же домене.

- [ ] **18. Не делать SEO-фабрику и английский продукт до первой сверки.** Страницы «расчёт каркасного дома», «спецификация пиломатериала», «раскрой доски» и `/en/wood-frame-bom` появятся из реальных кейсов, не из генерации текстов. До первой живой таблицы расхождений их не создавать. Готово, когда в репозитории нет этих страниц до даты первой сверки, и они появляются только как пункты 38–39.

## Где взять сто правильных контактов

- [ ] **26. Собрать сто карточек A и B, не «всех строителей».** Оценка A: на сайте, в объявлении или на видео человек прямо показывает каркасные дома и говорит о спецификации, смете, раскрое, SketchUp или «проект+комплект». Оценка B: делает каркасники, но workflow ещё не виден. Оценка C — архитектура вообще, ремонт, мебель, клееный брус, каменные дома — в таблицу не попадает. Цель: 100 строк A/B, из них не меньше 40 с телефоном. Ищи пачками по источникам ниже, в каждую карточку клади ссылку на конкретный объект, не на главную фирмы. Готово, когда в CRM ровно сто квалифицированных строк и ты можешь за минуту объяснить, почему каждая не C.

- [ ] **27. Profi.ru, Авито, Kwork, FL.ru.** На Profi.ru ищи «проектирование каркасных домов», «каркасный дом проект», «смета каркасного дома». На Авито — услуги и готовый бизнес в строительстве, карточки с портфолио каркаса, не «мастер на час». На Kwork и FL.ru — фрилансеры, которые продают чертежи каркаса, SketchUp и ведомости. В объявлении копируй имя, телефон, город и одну фразу про их объект в CRM. Готово, когда из этих четырёх площадок набрано не меньше 40 строк.

- [ ] **28. Яндекс Карты и 2ГИС.** Запросы: «каркасные дома», «строительство каркасных домов», «проектирование ИЖС» по городам, где виден поток частных домов. Открывай карточки компаний до 10 человек, не федеральные сети. Телефон, сайт, список проектов — в CRM. Если на сайте есть PDF комплектации или Excel-ведомость, это почти наверняка A. Готово, когда из карт набрано не меньше 25 строк.

- [ ] **29. Forumhouse, VK, Telegram, YouTube, Rutube.** На Forumhouse ищи компании и подписи в темах про каркас и комплектацию. В VK — группы подрядчиков с альбомами каркаса. В Telegram через TGStat — каналы «каркас», «ИЖС», «проектирование домов»; пиши владельцу канала или автору проекта, не спамь в общий чат объявлением. На YouTube и Rutube — ролики, где человек в SketchUp или на стройке показывает каркас и смету; телефон часто в описании. Готово, когда из этих каналов набрано не меньше 25 строк, и у каждой есть точка контакта.

- [ ] **30. Не трогать купленные базы и «парсер 10 000 директоров».** Холодный контакт разрешён только по публично оставленному телефону, форме или почте компании. Письма в США не начинай, пока не дойдёшь до пункта 44. Российские платежи проверяй на законность в момент выставления счёта, не на этапе списка. Готово, когда в CRM нет строк без публичного источника.

## Как звонить и что продавать

- [ ] **31. Поставить недельный ритм и не нарушать его разработкой «ещё одной фичи».** В неделю: добавить недостающих до текущей цели контактов, отправить или набрать 20–30 первых касаний, сделать follow-up тем, кто отозвался, провести 5 разговоров, выполнить 2 сверки, попросить рекомендацию после удачного пилота, опубликовать один разбор, исправить один дефект, который блокирует больше всего сверок. Время: примерно 40% разговоры, 30% сверки, 20% продукт, 10% короткие ролики и правки страницы. Готово, когда эта неделя записана в CRM датами, а не «я примерно так и делал».

- [ ] **32. Первое касание — про их объект, не про твой стартап.** Тема письма или первое сообщение: «Спецификация каркаса для проекта [название]». Текст: «[Имя], увидел ваш проект [конкретная деталь: мансарда 8×10, тёплый угол, ведомость в PDF]. Похоже, вы выдаёте спецификацию пиломатериала и раскрой. Я делаю FramePlan: он строит платформенный каркас и формирует ведомость и раскрой. Сейчас проверяю точность на уже завершённых проектах, а не прошу доверить ему новую стройку. Если дадите обезличенный старый проект, сравним результат с вашей ведомостью и зафиксируем каждое расхождение. Интересно проверить один объект?» Звонок начинается так же, только вслух. Не читай про искусственный интеллект, Беларусь, «платформу» и раунд инвестиций. Готово, когда шаблон вставлен в CRM и первые 20 касаний ушли по нему, каждое с уникальной деталью объекта.

- [ ] **33. Скрипт трубки.** Если берут: «Это Тимофей, пишу и звоню проектировщикам каркасных домов. Видел ваш [объект]. Подскажите, спецификацию пиломатериала и раскрой вы сейчас собираете в Excel вручную или из модели? Мне нужно не продать подписку, а сравнить вашу старую ведомость с расчётом программы на одном уже построенном или уже посчитанном доме. Если расхождения есть — вы получите таблицу, я — список ошибок. Если совпадёт — у вас будет файл на следующие объекты. Есть 20 минут на ваш последний дом?» Если «занят»: «Когда удобно завтра, 11 или 16 по Москве?» Если «не я»: «Кто у вас считает каркас и закупку?» Если «не интересно»: «Понял, больше не потревожу». Не больше трёх касаний без ответа: первое, напоминание с одной деталью их проекта, вежливое закрытие. Готово, когда 20 разговоров или попыток записаны в CRM с исходом.

- [ ] **34. Первые 15–20 минут разговора — без экрана FramePlan.** Спроси и запиши: откуда пришёл план; кто строил геометрию каркаса; где хранилась ведомость; что копировалось руками; сколько было ревизий; какая ошибка закупки или пересчёта была самой дорогой; сколько часов уходит на первый расчёт и на изменение стены; кто утверждает закупку. Не собирай комплименты. Цель — файл и стоимость процесса в часах или рублях. Готово, когда в CRM по разговору есть эти ответы, а не «вроде интересно».

- [ ] **35. Демо включай только на их доме, и продавай сверку, не «тариф Pro».** После вопросов покажи, как их план превращается в каркас и ведомость, затем скажи пакет: сверка завершённого проекта, таблица расхождений, PDF и CSV, следующие три проекта, 2 900 ₽, оплата по договору и чеку. Они оставляют обезличенный план и свою ведомость. Срок ответа с твоей стороны — 48 часов. Если не готовы платить сразу, сделай одну бесплатную сверку только в обмен на файл и разрешение обсудить расхождения; в постоянный бесплатный доступ это не превращается. Готово, когда у тебя на руках первый чужой план или явный отказ с причиной.

- [ ] **36. Провести сверку как продукт, а не как дружеский чертёж.** Построй модель, выгрузи PDF и CSV, заполни таблицу расхождений, классифицируй причины вместе с клиентом на втором коротком звонке. Не спорь «мы правы». Если дефект FramePlan — исправь движок и пересчитай эталон. Если неподдержанный случай — добавь в карту покрытия. Если ошибка их ведомости — покажи спокойно, это и есть ценность. Готово, когда клиент получил файлы, а у тебя записаны время на сверку, список расхождений и решение: использовать на следующем объекте или нет.

- [ ] **37. Взять деньги за пакет и сразу назначить следующий объект.** После нормальной сверки выстави 2 900 ₽ за уже сделанное плюс три следующих проекта, либо зачти бесплатную сверку в этот пакет, если так договаривались. Пробей чек, положи копию договора, в CRM поставь статус «оплачен» и дату следующего дома. Не выдавай бессрочный Pro. Готово, когда на счёте есть первая оплата, в таблице есть дата и сумма, клиент знает, какой объект идёт следующим.

- [ ] **38. Каждую сверку превратить в доказательство, а не в секрет.** С разрешения клиента, без адресов и фамилий заказчика дома, собери страницу кейса: что было на входе, какие допущения, их числа, наши числа, разница, причина, ограничение, кнопка «проверить свой старый проект». Из того же материала — короткий ролик и три кадра с подписями. Этим отвечай на Forumhouse и в переписке вместо абстрактного «у нас инновация». Готово, когда на `/ru/pro` стоит хотя бы одна реальная таблица, не выдуманная.

- [ ] **39. SEO-страницы делать только из кейса.** Когда есть первая реальная сверка, тогда появляются `/ru/specifikaciya-pilomateriala` и `/ru/raskroy-doski`: пример ведомости, чем BOM отличается от закупочного списка, зачем углы и проёмы, зачем ширина пропила, скачать шаблон, кнопка на сверку. Страница `/ru/raschet-karkasnogo-doma` может отдавать грубый диапазон пиломатериала и теплопотерь бесплатно, полный альбом — за пилот. Готово, когда эти страницы ссылаются на живой файл, а не на «Lorem ipsum каркас».

## Как понять, что бизнес пошёл, и когда остановиться

- [ ] **40. Дойти до цифр, без которых продукт ещё гипотеза.** Минимум: 20 разговоров с ICP, 8 чужих исторических проектов, 5 законченных сверок, 3 оплаты, ноль критических ошибок геометрии и BOM перед живым использованием, нет уникальной доработки под каждую фирму. По воронке на 100 квалифицированных контактов ориентир: письма доходят, человеческий ответ не меньше 8%, заинтересованных не меньше 4%, до разговора не меньше 3%, из разговора до файла не меньше 40%. Если доставляемость нормальная, а ответов нет — меняй, кому пишешь и какую боль называешь, а не цвет кнопки. Готово, когда эти числа стоят в одной вкладке CRM и обновляются раз в неделю.

- [ ] **41. Считать повтор, а не «MAU как у соцсети».** У каркасного проектировщика нет ежедневного захода. Смотри: взял ли он следующий подходящий дом, сколько объектов на компанию, как часто жмёт экспорт, предоплатил ли пакет проектов. Сильный сигнал: 70% используют инструмент на следующем доме, 50% — на трёх, часть просит уже не разовую сверку, а регулярный доступ. Готово, когда после трёх оплат ты видишь хотя бы одну вторую живую стройку в CRM.

- [ ] **42. Остановить или сменить модель по правилам, не по настроению.** Закрывай или радикально меняй оффер, если после честной проверки платят меньше трёх из двадцати квалифицированных, если повтор меньше 40%, если выход нельзя довести до нуля критических ошибок, если одна компания требует отдельную ветку программы, если поддержка съедает маржу, если покупают только ручное черчение, если единственная ценность — обещание заменить инженера, если законный приём денег так и не подтверждён. Тогда не «добавляй 3D». Тогда смотри узкие развилки из плейбука: движок как API, белая марка для одного производителя, платная сверка как услуга без SaaS, конфигуратор для поставщика. Готово, когда решение записано датой и цифрами, а не ощущением «надо ещё фич».

## Только после трёх оплат и повторного дома

- [ ] **43. Тонкое облако, когда файлы в браузере начинают теряться.** Magic-link по почте, список проектов, снимки версий, ручная выдача доступа после перевода, логотип компании на PDF, сравнение «до переноса стены / после», ссылка только на просмотр отчёта, кнопка «собрать пакет для поддержки». Карточный checkout всё ещё не обязателен. Готово, когда клиент открывает свой дом на втором компьютере без твоей пересылки JSON в Telegram.

- [ ] **44. Английский тест спроса без американских норм.** Страница `/en/wood-frame-bom` с заголовком «Turn a wood-frame layout into reviewable framing geometry and a cut-ready BOM», оффер сверки completed job, без signup в «US code software». Интерфейс и сортамент — только если 20 разговоров и три условные оплаты этого теста этого требуют. Готово, когда английская страница существует как тест, а в PDF всё ещё нет фразы про IRC/IBC compliance.

- [ ] **45. Пакет норм другой страны — только после 3–5 платящих в одной юрисдикции.** Не «международный FramePlan». Общее ядро плюс именованный RulePack с редакцией норм, климатом участка, местным сортаментом и эталонными домами местного проверяющего. Пока кластера нет, этот пункт закрыт. Готово, когда есть письменные партнёры в одной юрисдикции и отдельный набор тестов, который не ломает российский эталон.
